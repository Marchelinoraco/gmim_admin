Autentikasi & Onboarding

Empat tombol di landing → tiga alur masuk, plus model peran (RBAC) dan akses dukungan Super Admin.

Masuk → Alur A Coba Demo → Alur B Daftar Gratis → Alur C Hubungi Admin → dibantu

Alur A · Login tanpa memilih gereja (Sanctum, same-origin)

MVP (KF-2): login by email unik global ke modul auth di gmim_api; sistem menentukan gereja → redirect /g/<slug>. Tanpa duplikasi user (satu tabel ber-email unik), tanpa OIDC/JWT.

sequenceDiagram
    autonumber
    actor U as User
    participant FE as gmim-keuangan.id (UI login)
    participant API as gmim_api (modul auth)
    U->>FE: email + password
    FE->>API: POST /auth/login
    API->>API: verifikasi (email unik global)
    API->>API: resolusi gereja user → slug
    API-->>FE: { token Sanctum, slug, role }
    FE->>FE: simpan token (localStorage)
    FE->>API: GET /gereja/{slug}/... + Bearer
    API->>API: EnsureUserBelongsToGereja → cocok?
    API-->>U: Dashboard gereja (/g/)

Versi SSO/OIDC (service terpisah, JWT/JWKS) = peningkatan masa depan — Bagian 07 (ditunda).

Alur C · Pendaftaran Mandiri

Pendaftar otomatis menjadi Admin Gereja. Gereja + langganan trial + user + seed dalam satu transaksi di gmim_api (modular monolith).

sequenceDiagram
    autonumber
    actor U as Calon Gereja
    participant R as gmim-keuangan.id/daftar
    participant API as gmim_api
    U->>R: nama gereja, alamat, bendahara, slug, email, password
    R->>API: POST /auth/register
    API->>API: validasi slug unik+reserved, email unik global
    Note over API: TRANSACTION
    API->>API: gereja (slug, status=trial)
    API->>API: langganan (trial, +14 hari)
    API->>API: church_user (email, role=admin_gereja)
    API->>API: seed kategori + aset + "Gaji & Honor"
    Note over API: COMMIT (+ email verifikasi)
    API-->>R: { token, slug }
    R-->>U: redirect gmim-keuangan.id/g//dashboard
