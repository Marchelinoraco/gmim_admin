Keamanan & RBAC

Menjamin "tidak ada gereja yang bisa melihat data gereja lain" — pertahanan berlapis, key Midtrans, & akses Super Admin ber-audit.

Pertahanan Berlapis

0Origin (subdomain) — cookie/storage terpisah per gerejamasa depan
1Transport — HTTPS+HSTS, CORS allow-list *.gmim-keuangan.id
2ResolveTenant — set gereja_id aktif
3auth:sanctum — user dari token (login by email global) (ada)
4EnsureUserBelongsToGereja — user.gereja_id == /g/<slug> → 403 (ada)
4bEnsureSubscriptionActive — tolak mutasi bila langganan expired (402) (baru, 08)
5EnsureRole — gate per peran (sebagian)
6Global Scope BelongsToGereja — WHERE gereja_id otomatis (BELUM — wajib)
7Uji isolasi di CI — A tak bisa baca/tulis B (BELUM — wajib)
Blocker go-live: lapis 6 & 7 belum ada. Tanpa Global Scope, satu query yang lupa filter bisa membocorkan data antar gereja.

Keamanan Key Midtrans

🔒 server_key terenkripsi at-rest (encrypted cast)
🙈 server_key tak pernah dikirim ke FE (masked)
✍️ server_key write-only dari UI (kosong = jangan ubah)
🔑 client_key boleh ke FE (Snap.js)
✅ Webhook verifikasi signature SHA-512 + idempoten by order_id
🏦 Akun Midtrans per gereja → dana ke rekening gereja
